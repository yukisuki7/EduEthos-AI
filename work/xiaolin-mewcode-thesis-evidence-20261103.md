## 公开页可以核实的描述

[MewCode 官方介绍](https://www.xiaolincoding.com/project/mewcode.html) 将项目定位为 CLI Coding Agent，介绍 Agent Loop、文件/命令工具、MCP、技能、Hook、上下文/记忆及多 Agent 等功能，并称提供 Java/Go/Python/TypeScript 版本。以上是作者的功能与实现声明，不是本次源码或运行验证结果。

页面学习方式与 FAQ 说明以飞书图文为主，没有手把手视频教学，提供开发提示词和源码。模型/AI编程套餐不随课程赠送；页面对学习周期、低模型花费与求职效果的表述不能作为用户实际成本或效果保证。购买权益包含源码，本次没有取得可审查的 MewCode 项目代码或确认其二次分发许可。

## 需要澄清的技术边界

- 通用 Coding Agent 可以是系统型毕设候选，不要求为了业务场景强行包装成校园助手；是否接受 CLI 工具、如何认定独立实现，由学院规范决定。
- 工具调用循环停止不等于任务正确完成。代码修复应通过预设测试、回归与人工检查等独立证据确认。
- Git worktree 用于同一仓库的多个工作树和分支，不应等同操作系统沙箱；文件、命令、网络和凭证边界仍需独立处理。[Git 官方 worktree 文档](https://git-scm.com/docs/git-worktree)
- 多 Agent、压缩和记忆的效果应在相同模型、任务和预算下比较，不能根据模块名称推断一定更准确、更快或更省。

## 毕设范围建议（设计判断，尚未实现）

MewCode 方向可收敛为小型 Python 仓库的代码修复工具，完成“理解任务—查找相关文件—生成待审查补丁—运行预设测试—有限重试—保存执行证据”。限制仓库规模、语言和工具权限；先不扩展多语言、长期 Agent Teams 或通用软件开发。

可固定任务集，对比直接模型生成、带工具循环和改进的上下文/执行策略，报告修复成功率、回归失败、超预算、模型调用量与时间。测试通过只表示测试覆盖的条件满足，不代表补丁全面正确。

[DevFlow 官方介绍](https://www.xiaolincoding.com/project/devflow.html) 的领域是研发数据与协作，可考虑收敛成 CI 失败诊断。将日志与具体仓库/提交绑定，提取错误、检索相关代码和资料、输出带证据的诊断与建议；先保持只读，避免同时承诺 Issue 分诊、PR 审查、周报、多 Agent 发布决策和自动修复。用自建可复现失败案例与人工核对标准答案评测；比较单 Agent 与多 Agent，不预设后者有收益。

以上功能原课程可能已有，不能直接当作新增贡献。取得源码后，需记录原始版本、明确复用模块，选择自己具体实现或改进的问题，并用相同条件的前后对照证明结果。

## 选择建议

以普通本科系统型毕设为前提：偏课程助学的用户可继续此前受控的课程资料答疑与复习规划路线；愿意改成研发工具题目时，优先考虑 DevFlow 中单一诊断场景；明确希望理解 Agent 引擎、文件编辑和命令执行时，再选 MewCode 的有限代码修复方向。本判断不代表课程品质、就业效果或选题审核保证。
