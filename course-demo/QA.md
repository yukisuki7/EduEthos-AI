## 2026-11-03 DeepSeek 线上连接错误修复

- 用户实际提问返回“暂时无法连接 DeepSeek，请稍后重试”。生产日志确认两次 `POST /api/chat` 返回 502，wall time 为 11/13 ms；托管 DeepSeek 配置和体验账号配置均存在，非未配置模型。
- 根因：出站请求使用 `redirect: 'error'`。Cloudflare Workers 不实现此模式，在真正发出请求前抛 TypeError；本地 Node 的 fetch 与原模型桩未覆盖这个运行时差异。依据：https://developers.cloudflare.com/workers/runtime-apis/request/ 。
- 增加平台约束回归检查，先重现相同 502/model_unreachable 后，将请求改为 `redirect: 'manual'`，对 3xx 明确拒绝并取消响应体，避免 Authorization 转发到其他地址。检查同时验证重定向不跟随、不重试、不泄漏目标或上游正文。
- 修复后构建、check-worker、check-demo-auth、check-demo-ui、check-state 和 diff 检查通过。真实浏览器工具仍因 kernel assets 路径错误无法启动，本机直接请求站点仍被 Cloudflare 403 拦截；因此这些检查不等同于修复后的线上真实 DeepSeek 回答验证。
- 独立实际运行时复现：项目目录下安装官方 `workerd@1.20261103.1`（输出 workerd 2026-11-03），真实 Worker 中 `Request` 使用 error 模式返回 TypeError，manual 模式正常构造。此项验证运行时兼容性，未读取密钥、未调用真实模型；脚本和下载位于项目 `.tools/worker-runtime-check/`。
